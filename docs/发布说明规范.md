# 发布说明规范

面向对象是**用软件的人**（喷绘厂的操作员、老板），不是开发者。三条，缺一不可。

## 1. 第一句就让人知道「这次能干什么」

不超过 **40 字**，不要专业名词，不要「优化了底层架构」这种空话。

- ✅ 打印机能认我们转出来的图片了。
- ✅ 关掉更新窗口也不会中断下载。
- ❌ 重构了 JPEG 编码管线，改用 libjpeg 重写 DQT/DHT 段。

## 2. 只写用户能感知的变化，不写实现

不出现任何实现细节词：**JPEG / EXIF / DRI / DQT / YCCK / libvips / 句柄 / 缓存 / 线程 / API / 编码器**。
判断标准：用户看到这句话，能不能想象出「界面上/处理结果上会发生什么」。

- ✅ 设置页里不再有「网络加速」开关，加速默认一直开着。
- ❌ 把 ProxyMode 强制写成 SystemWide 并移除了绑定。

## 3. 具体修了什么，用「以前……现在……」举一个例子

一个例子胜过三条形容。举最能代表这次修复的场景，写清楚前后差别。

- ✅ 以前在网络盘上处理完图片，改个名会提示「文件已被占用」；现在处理完可以立刻改名、删除。
- ✅ 以前关掉更新窗口，下载就断了；现在会继续下完，只会在托盘提示。

### 写完自查

1. 第一句能不能读给非技术同事听，他点头说「懂了」？
2. 通篇搜一遍有没有第 2 条列的词，有就换成人话。
3. 有没有一处「以前……现在……」的具体例子？
