# PRD · 内置 GitHub 加速代理与在线自动更新

> 产品：正画 PivotPic（Windows WPF 桌面应用，当前 v1.2.45）
> 目标版本：v1.3.0　|　类型：功能增强（P0 基础设施）

## 1. 项目信息

| 项 | 内容 |
|---|---|
| Language | 中文 |
| Programming Language | C# / .NET 8 + WPF（沿用现有工程，不引入新框架） |
| Project Name | `pivotpic_github_updater` |
| 原始需求 | 大陆网络访问 GitHub 不稳定，「检查更新」经常失败。内置开源代理 gitport-github（Apache-2.0，Rust，单文件 exe ≈7 MB），为检查更新与安装包下载提供加速，并实现完整的在线自动更新闭环。 |

**与现有工程的关系（调研结论）**

- 版本号已由 `Services/AppInfo.cs` 统一提供（`VersionText`），关于页 `Views/AboutPage.xaml` 已展示版本 —— 更新模块复用该来源，不新增版本常量。
- 设置页 `Views/SettingsPage.xaml` 现有区块：行为 / 处理上限 / 外观 / 启动 / 配置 / 目录占位符。
- 数据目录 `Services/AppPaths.cs`：安装目录可写则用安装目录，否则回退 `%AppData%\PivotPic`。**代理工作目录必须落在 `AppPaths.DataRoot\proxy\`**，因为 gitport 首次运行需在自身目录写 `ca.crt/ca.key/routes.json/settings.json`，装在 `Program Files` 时会写失败。
- 卸载器 `PivotPic.Uninstaller` 需新增「清证书 + 还原 PAC + 停代理进程」。

## 2. 产品定义

### 2.1 产品目标（一句话）

让用户在大陆网络下也能稳定、无感地完成「检查更新 → 下载 → 安装」，代价是用户对一次性授权（根证书）有完整知情权与随时撤回权。

### 2.2 非目标（明确不做）

1. 不接管非 GitHub 域名流量，不做全局 VPN / 科学上网工具。
2. 不代理图片处理相关的任何网络流量（本软件本身不联网处理图片）。
3. 不做后台常驻更新守护、不强制升级、**不静默安装**。
4. 不做跨大版本自动迁移（v2 需用户手动安装）、不做增量更新 / 差分包（143 MB 全量包先跑通）。
5. 不在用户未授权的情况下写入任何系统级设置（PAC / 证书）。

### 2.3 代理作用域（关键设计决策）

默认**只服务本进程**：更新模块的 `HttpClient` 显式设置 `WebProxy = 127.0.0.1:7810`，不修改系统代理、不写 PAC。理由：本软件只需要访问 GitHub，系统级接管带来额外的还原风险与杀软误报，收益为零。

「系统级 GitHub 分流接管（写 PAC）」作为**可选高级开关**，默认关闭，仅对 GitHub 域生效，退出自动还原。

### 2.4 用户故事

1. 作为**新用户**，我想在首次开启「自动检查更新」时看到一次性授权说明并自己决定是否启用增强模式，以便我在知情前提下使用，而不是被静默改系统。
2. 作为**日常用户**，我想在启动软件后自动、安静地检查新版本而不被弹窗打断，以便我继续处理图片。
3. 作为**发现新版本的用户**，我想在托盘和主界面看到不打断操作的提示，并能查看版本号、日期、更新说明与包大小，以便我判断是否值得升级。
4. 作为**决定升级的用户**，我想一键下载并在校验通过后自动进入安装，失败时能看到原因和重试入口，以便我不会装上一个损坏或被篡改的包。
5. 作为**隐私敏感用户**（公司电脑），我想关闭自动更新并一键移除已安装的证书，以便软件不再触碰任何系统级配置。

## 3. 开关与状态机（核心）

### 3.1 「检查更新」总开关

| 开关 | 触发动作 | 不做的事 |
|---|---|---|
| 关 → 开 | 启动代理（`启动中`）→ 就绪后延迟 5s 静默检查；写入 `AutoCheckEnabled=true` | 不立刻弹任何窗口 |
| 开 → 关 | 停代理进程 → 还原 PAC（若曾接管）→ 取消进行中的检查/下载 | **不**自动移除证书（避免反复授权；移除需用户显式操作） |
| 首次启动（`AutoCheckEnabled` 未初始化） | 默认视为「开」，但**不自动启动代理**；第一次静默检查走直连，失败后才引导开加速 | 不自动装证书 |
| 程序退出（托盘退出/更新安装前） | 停进程 → 还原 PAC → 退出 | 不弹确认框 |

### 3.2 代理运行状态机

| 状态 | 进入条件 | UI 呈现 | 自动动作 | 可转出到 |
|---|---|---|---|---|
| `Off` 未启用 | 总开关关 / 用户关闭加速 | 灰点「未启用」 | 停进程、还原 PAC | Starting |
| `Starting` 启动中 | 开关打开 / 崩溃后重启 | 黄点「启动中…」 | 拉起 `gitport-github.exe -headless`，轮询 `127.0.0.1:7811` 就绪，超时 5s | Running / Failed |
| `Running` 运行中 | 探测成功；增强模式下额外校验证书指纹存在 | 基础：绿点「加速中 · 127.0.0.1:7810」；增强：绿点「加速中（增强）」 | 每 30s 心跳（管理页 GET）；进程 `Exited` 事件监听 | Failed / CertPending |
| `CertPending` 证书未授权 | 用户点「启用增强」但未同意 / 证书被手动删除 | 黄点「待授权，当前为基础加速」 | 保持基础加速；**不自动弹卡片**（仅首次引导时弹一次） | Running·基础 / Running·增强 |
| `Failed` 启动失败 | 起不来 / 端口全占 / 心跳连续 3 次丢失 | 红点 + 具体原因 | 自动重启 ≤2 次（间隔 5s、15s）；仍失败 → 降级直连，提示一次 | Starting / Off |

**状态写入时机**：所有状态变化同步写日志（`logs/app-yyyyMMdd.log`）并在设置页即时刷新，不依赖重启。

### 3.3 证书（增强模式）与授权流程

| 环节 | 规则 |
|---|---|
| 何时需要证书 | 仅在启用「增强模式（MITM）」时；基础透传模式不需要证书，也不需要任何系统写入 |
| 授权方式 | **软件内自绘授权卡片**（非系统对话框），用户点「同意并启用」后由程序自动写入 `CurrentUser\Root`（不需管理员），全程不进系统界面 |
| 持久化 | `CertConsent = Granted / Declined / None`。`Granted` 之后切换开关**不再询问**；`Declined` 之后也不再自动弹，只能从设置页手动发起 |
| 作用域 | 只对 GitHub 系域名签发；卡片文案必须明说这一点 |
| 校验 | 证书指纹存 `CertThumbprint`；每次检查前与启动时按指纹查存储区，缺失则置 `CertPending` 并静默回退基础模式 |
| 移除入口 | 设置页「移除证书」→ 二次确认 → 删证书 → 回退基础模式 → 更新 `CertConsent=Declined` |
| 卸载 | 卸载器执行前按指纹删除证书、还原 PAC、结束 gitport 进程 |
| 拒绝出口 | 卡片必须有次要按钮「暂不启用（仅基础加速）」，关闭卡片等同拒绝 |

### 3.4 关闭 / 退出的优雅退出顺序（顺序不可调整）

1. 取消进行中的下载与检查（`CancellationToken`）。
2. 调用管理页退出接口（须带请求头 `X-GitPort-Request: 1`），等待最多 3s。
3. 超时则 `Process.Kill(entireProcessTree: true)`，并记 `Warn` 日志。
4. 若曾开启系统级分流 → 触发 PAC 还原，再次读取确认已还原。
5. 清理临时下载目录残留（仅本次会话产生的文件）。

### 3.5 异常路径

| 异常 | 检测方式 | 处理 | 用户感知 |
|---|---|---|---|
| gitport 启动失败（文件缺失 / 被杀软拦截） | 进程退出码 + 无监听 | 重试 1 次 → 降级直连 | 设置页红点 + 首次一次 Toast「加速不可用，已改用直连」 |
| 端口被占用 | 绑定探测 | 7810→7819 顺序探可用端口并回写配置；全部占用则 `Failed` + 直连 | 区段内有空位无感；全占显示红点「端口被占用，已改用直连」 |
| 证书写入被拒（UAC / 杀软 / 策略） | 写入返回错误码 | 回退基础模式，**不循环弹卡片** | Toast「未授权，已使用基础加速」 |
| 证书被用户手动删除 | 启动时 + 每次检查前按指纹查 store | 置 `CertPending`，静默回退基础模式 | 设置页黄点 |
| 代理中途崩溃 | 进程 `Exited` / 心跳失败 | 重启 ≤2 次（5s / 15s）→ 降级直连 | 一次 Toast |
| PAC 残留（上次异常退出 / 被任务管理器强杀） | 启动时读 PAC 配置，判断是否指向本程序 | 自动还原 | 无感 |

## 4. 更新检查与提示

### 4.1 检查时机与请求

- 启动后延迟 5s 在后台检查（`Task.Run`，不阻塞 UI、不阻塞图片监控主流程）。
- 之后每 24h 检查一次（软件常驻托盘时）；两次检查间使用 `ETag / If-None-Match` 缓存，避免触发 GitHub 未认证 60 次/小时的限流。
- 数据源：`GET https://api.github.com/repos/{owner}/{repo}/releases/latest`，读 `tag_name`、`published_at`、`body`、`assets[]`（含 `size`、`browser_download_url`）。更新包为整份 Setup exe（143 MB，超 GitHub 单文件 100 MB 限制 → 只能作 Release 资产，不能进仓库）。
- 版本比较用 `Major.Minor.Build` 三段数值比较，忽略 tag 前缀 `v`；预发布版不参与（P2 再议）。

### 4.2 新版本提示方式（建议）

**建议：三级提示，不用模态弹窗。**

| 层级 | 位置 | 内容 | 理由 |
|---|---|---|---|
| 1 | 托盘图标气泡 / 托盘右键菜单新增「有更新 v1.3.0」 | 一次性气泡，10s 自动消失 | 软件常态最小化到托盘；用户不一定看着主窗 |
| 2 | 主窗口底部横幅（`监控中` 状态栏上方） | 「发现新版本 v1.3.0 · 查看详情 / 忽略」 | 不打断图片处理流程，可延后处理 |
| 3 | 关于页版本号旁「有更新」徽标 | 点击进更新弹窗 | 用户主动查找时的入口 |

**为什么不用模态弹窗**：核心价值是「静默处理图片」，模态窗打断操作，而用户常在托盘态根本看不到。更新是非紧急动作，应可延后；只有用户点了横幅/菜单才打开唯一的模态「更新详情弹窗」。

### 4.3 更新弹窗信息项

| 信息 | 说明 | 必需 |
|---|---|---|
| 版本号 | `v1.2.45 → v1.3.0`，旧版→新版对比展示 | P0 |
| 发布日期 | 取 `published_at`，本地化为 `2026-11-07` | P0 |
| 更新说明 | 渲染 `body` 中的 Markdown（纯文本降级，不做完整 MD 渲染） | P0 |
| 包大小 | 取 `assets[].size`，显示 `143.2 MB` | P0 |
| 下载进度 | 百分比 + 已下载/总量 + 速度 | P0 |
| 加速来源 | 「内置加速 / 第三方加速 / 直连」，透明展示当前通道 | P0 |
| 按钮 | `立即更新`（主）、`稍后`（次）、下载中变 `取消`；失败态变 `重试`；附「不再提示此版本」复选（P1） | P0 |

### 4.4 「立即更新」完整链路

1. **下载** → `%TEMP%\PivotPic\update\{version}\PivotPic-Setup-{version}.exe`，流式写盘，报进度，可取消（取消即删临时文件）。
2. **换源**：`内置代理直连` → `https://gh-proxy.com/` + 原始 asset URL → 直连（无代理）。每次失败换下一源，单源最多重试 1 次，总计 ≤3 次，退避 2s/5s。弹窗状态同步显示当前「加速来源」。
3. **校验** → 计算 SHA256，与 Release 内提供的 `checksums.txt`（同 Release 资产）比对。不一致 → 删除文件、拒绝执行、提示「安装包校验失败，已删除」，提供重试。
4. **启动安装** → 提示「即将关闭正画并开始安装」→ 以 `--wait-pid {当前进程 PID}` 参数启动 Setup（安装器需新增该参数以等待宿主退出，否则文件占用会导致安装失败）。
5. **退出** → 按 §3.4 顺序停代理、还 PAC，然后退出当前程序（走托盘退出流程，不是 `Environment.Exit`）。

### 4.5 失败与降级策略

| 场景 | 处理 | 是否打扰用户 |
|---|---|---|
| 代理不可用 / 启动失败 | 自动改直连检查 | 静默检查：不打扰；手动检查：弹窗提示失败原因 |
| 静默检查失败（网络/限流） | 只写日志；设置页显示「上次检查失败（网络）· 时间」 | 不打扰 |
| 下载失败 | 换源重试（最多 3 次），全失败 → 弹窗「下载失败」+「重试」+「浏览器打开 Release 页」 | 弹窗（用户已主动点过立即更新） |
| 校验不通过 | 删包 + 提示 + 重试；连续 2 次失败 → 只保留「手动下载」出口 | 弹窗 |
| 安装器启动失败（被拦/文件被删） | 弹窗提示 + 日志记录，临时目录保留 24h 便于排查 | 弹窗 |
| 磁盘空间不足 | 下载前检查可用空间 ≥ 包大小 × 2，不足直接拒绝并提示 | 弹窗 |

## 5. 授权卡片文案（完整中文，直接可落地）

**标题**：启用 GitHub 加速需要一次授权

**正文（约 100 字）**：

> 为稳定访问 GitHub 检查更新，正画会在本机安装一张专用根证书，用于解密经内置加速代理转发的 GitHub 加密流量。证书只对 GitHub 域名生效，不涉及其他网站；可随时在设置中移除，卸载时自动清除。

**三条要点**：

1. **只对 GitHub 域生效** —— 仅 `github.com`、`api.github.com`、`objects.githubusercontent.com` 等 GitHub 域名经过代理，其他网站不接管、不解密。
2. **可随时移除** —— 设置 → 更新与网络 → 移除证书，立即失效，无需重启；卸载软件时自动清除。
3. **只在本机运行** —— 代理仅监听 `127.0.0.1`，不向任何第三方服务器转发你的数据。

**按钮**：`同意并启用`（主，强调色）　|　`暂不启用（仅基础加速）`（次要）
**关闭（X）= 暂不启用**，与次要按钮同效。选择后持久化，不再自动弹。

## 7. 需求池

**P0（必须）**
- 自动检查更新总开关 + 启动延迟 5s 静默检查（不阻塞 UI）
- 代理进程启停、参数 `-headless`、端口探测 7810–7819、健康心跳、崩溃重启 ≤2 次
- 五态状态机与设置页状态呈现
- 新版本提示三级通道（托盘气泡 + 主窗横幅 + 关于页徽标）
- 更新弹窗（版本/日期/说明/大小/进度/加速来源）
- 下载 → SHA256 校验 → 启动安装器（等待宿主退出）→ 退出程序
- 失败降级：代理不可用转直连、下载换源重试、校验失败拒绝执行
- 授权卡片（自绘、含「暂不启用」出口、选择持久化）+ 证书自动写入 + 移除入口
- 退出/关闭开关时优雅退出代理并还原 PAC；卸载器清理证书与 PAC
- 全链路日志（复用 `LogService`）

**P1（应该）**
- 系统级 GitHub 分流 PAC 开关（默认关，退出自动还原）+ PAC 残留自愈
- 「不再提示此版本」（`SkippedVersion`）
- 下载速度 / 剩余时间显示；失败时「浏览器打开 Release 页」
- 安装包 Authenticode 签名 + 公钥验签（SHA256 只能防损坏，不能防篡改）

**P2（可选）**
- 检查频率用户可选（启动 / 每日 / 每周）
- Beta 预览渠道
- 增量更新 / 差分包
- 代理节点测速与择优

## 8. 配置项新增（给架构师的输入）

`AppConfig` 追加（`SchemaVersion` 需 +1 并兼容旧配置缺字段）：

| 字段 | 类型 | 默认 | 用途 |
|---|---|---|---|
| `AutoCheckEnabled` | bool | true | 总开关 |

## 9. 待确认问题

1. **仓库地址与资产命名未定** —— `owner/repo` 是什么？Release 资产命名是否统一为 `PivotPic-Setup-{version}.exe`？`checksums.txt` 是否随 Release 一起上传？（影响更新源硬编码位置与校验实现）
2. **GitPort 是否必须装系统级证书才生效？** 若它支持「仅本进程代理 + 进程内信任自带 CA」，我们可以完全不碰系统证书区（更安全、更少杀软误报）。需先做一次真实环境验证（360 / 火绒 / Defender + 企业策略），再决定授权卡片是 P0 还是「仅在系统级分流时出现」。
3. **检查频率是否暴露给用户** —— 固定「启动 + 每 24h」是否够用，还是要给三档选择（会稀释设置页的简洁度）？
4. **是否允许「跳过此版本」** —— 允许可能让用户长期停在旧版；不允许则每次启动都提示可能招致反感。建议允许（P1），需确认。
5. **安装器能否新增 `--wait-pid` 参数** —— 这是自动更新能否一键完成的前提；若不改安装器，只能退化为「先退出软件，再由用户手动双击安装包」。
